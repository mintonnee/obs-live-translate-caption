표시 중인 구간의 교체와 적체 제한을 분리해 다룬다. 번역 품질 판정과 교정 요청 생성은

## 1. 목표와 비목표

검증 문장:

```text
긴 발화의 안정된 구간은 발화 종료 전에 번역되어 최근 줄 창에 순서대로 누적 표시되고, 같은 final 발화는 줄 폭 안에서 이어지며, 최신 표시 갱신 뒤 설정한 유지시간 동안 자막이 남고 이전 응답이나 만료된 자막은 다시 나타나지 않는다.
```

### 목표

| 영역 | 목표 |
|---|---|
| 분할 | final 원문은 짧은 구간으로 나누고 interim은 안정된 앞부분에서만 선행 번역한다. |
| 식별 | 화면 문자열에 구분자를 삽입하지 않고 발화·구간 ID와 버전으로 요청, 응답, 표시를 연결한다. |
| SMART 수정 | 수정된 원문을 버리지 않고 최신 원문으로 대체한다. 확정 전 안정성은 추정이며 final과 대조한다. |
| 표시 | 구간을 보관하고 렌더링 시 줄바꿈한다. 긴 번역은 페이지로 나누고 최근 줄 창에 누적하며 표시 중 수정은 해당 위치를 교체한다. |
| 동시성 | 3개 번역 워커를 유지하고 오래된 작업, 역순 응답, 설정 변경, 정지·재연결을 격리한다. |
| 지연·메모리 | 작업 수, 대기 시간, 원문 보관량에 상한을 두고 명시적인 사유로 만료시킨다. |
| 확장 계약 | `006`의 같은 원문 재번역을 수용하는 작업 식별자와 결과 반영 규칙을 제공한다. |

### 비목표

| 항목 | 제외 이유 |
|---|---|
| 미번역 판별, 언어별 프롬프트, 자동 재번역 생성 | `006`의 책임이다. 이 문서는 결과 반영 계약만 정의한다. |
| 무손실 녹취·무한 자막 보관 | 실시간 방송에서 유입량이 표시·번역 처리량을 지속적으로 초과할 수 있다. 한도 초과 시 최신성 우선으로 만료시키며 누락을 계측한다. |
| 화면에서 사라진 내용의 별도 정정 자막 | 과거 자막 재노출과 추가 적체를 방지한다. 이 단계에서는 표시 중인 내용만 교체한다. |
| 매 N초 오디오 강제 종료, 수동·Hybrid VAD 도입 | 음성 스트림 경계 변경 없이 텍스트 분할 효과부터 검증한다. 안정 구간이 없는 연속 발화의 지연 상한은 보장하지 않는다. |
| 고급 형태소 분석기·임베딩·추가 LLM 분할 호출 | 의존성, 실행 비용과 지연을 늘리지 않고 결정적 로컬 규칙으로 시작한다. |
| 생성 모델의 출력 토큰 잘림 해결 | 이 문서의 페이지 분할은 수신한 번역문을 대상으로 한다. 기존 출력 토큰 상한을 유지하며 모델 단계 누락을 무손실로 해결했다고 주장하지 않는다. |

## 2. 성공 기준

1. 공백 포함 final과 공백 없는 한글·가나 final을 분할하면 정규화된 원문 순서를 보존하고, 내용이 중복·누락되지 않으며 UTF-8 코드 포인트 중간에서 끊기지 않는다. 한도 초과 입력은 기준 12의 명시적 예외로 처리한다.
2. §4.2의 시간·관측 수를 충족한 interim에 의미 경계가 있으면 final 이전에 작업이 생성된다. 아직 불안정한 꼬리, 동일 interim 반복, 타이머 tick만으로는 새 작업을 만들지 않는다.
3. 중복 interim 및 선행 번역과 동일한 final은 새 번역을 만들지 않는다. final에 새 꼬리가 있으면 그 부분만 추가하고, 수정된 부분은 기준 4로 처리한다.
4. SMART 삽입·삭제·치환, 숫자·부정 변경, 구간 병합·재분할을 재생하면 수정된 원문이 현재 상태가 된다. 동일 구간은 원문 버전을 올리고 경계 변경은 대체 관계를 기록한다. 문자열 길이 오프셋만으로 final의 앞부분을 제거하지 않는다.
5. 응답을 `(v2,a1) → (v1,a1)`, `(v2,a2) → (v2,a1)` 순으로 주입해도 최신 번역이 이전 번역으로 바뀌지 않는다. 중복 성공·실패 이벤트는 멱등이고 구버전 실패는 현재 구간을 실패시키지 않는다.
6. 세그먼트 A·B·C 응답이 C·A·B 순으로 도착해도 최소 표시 간격을 두고 A·B·C 순서대로 누적된다. 확정 여부와 발화 경계에 관계없이 연속 세그먼트는 공백으로 연결하고, 합친 표시 폭이 `caption_max_chars_per_line`을 넘을 때 감긴다. 텍스트의 명시적 줄바꿈은 유지한다. 한 줄에 모두 들어가는 경우 `A → A B → A B C`로 표시하며, 줄 수를 넘으면 가장 오래된 줄부터 밀려난다. 한 tick에 완료 결과를 전부 소비하여 B가 표시되지 않는 일이 없다. 실패·만료한 구간만 사유를 남기고 건너뛴다.
7. 현재 활성 A의 수정 번역은 최근 줄 창의 A 위치를 교체하고 다음 B 앞이나 뒤에 새 항목으로 추가되지 않는다. 재번역 중 기존 결과가 유지되고, 성공한 수정 결과가 실제 표시되면 그 시점부터 최소 표시 시간과 `caption_hold_seconds`를 다시 계산한다. 실패·구버전·중복 결과는 유지시간을 연장하지 않는다.
8. 2줄 박스에 4줄로 감기는 결과는 정상 부하에서 2페이지 모두 표시된다. 각 페이지는 최근 줄 창 아래에 누적되고 초과한 가장 오래된 줄만 밀려난다. 수정·과부하·만료가 없으면 페이지 내용이 표시 순서에서 건너뛰어지지 않는다. `002`의 일반적인 초과 줄 `…` 절단은 이 정책으로 대체된다.
9. 표시 종료·폐기·대체된 구간의 성공/실패 응답은 화면을 다시 만들지 않는다. 실제 화면을 바꾼 최신 성공 결과와 현재 표시 중인 발화의 최초 final 수신이 만료 시각을 갱신한다. 표시 수명 갱신 자체는 추가 번역 요청·페이지 최소 표시 시간·전체 표시 수명을 다시 시작하지 않는다. final 대조로 작업이 무효화돼도 표시 중인 창은 새 결과 또는 hold 만료까지 유지한다. 단일 페이지와 마지막 페이지는 15초 전체 표시 수명보다 긴 `caption_hold_seconds`도 온전히 지킨다.
10. 가짜 HTTP 전송기로 3개 작업을 보류하면 네 번째 작업은 시작하지 않는다. 같은 구간의 아직 시작하지 않은 작업은 최신 원문으로 합쳐지고, 네트워크 I/O 동안 오디오·상태 락을 보유하지 않는다.
11. 정지, 재시작, 키·대상 언어·번역 모델·사전 변경, STT 재연결 후 이전 세대의 콜백이 도착해도 작업과 표시가 부활하지 않는다. 변경 뒤 처음 생성되는 요청에는 새 설정 스냅샷만 들어간다.
12. 1,000개 합성 구간 폭주 및 매우 긴 interim/final을 입력해도 §4.5의 개수·바이트·시간 상한을 넘는 상태가 유지되지 않는다. 폐기 사유와 수가 기록되고 활성 페이지는 최소 표시 시간을 지킨다.
13. `caption_incremental_translation=false`에서는 final만 번역하며 분할·버전·페이지 처리는 유지된다. 박스·hold 설정과 `004` 일시정지 동작이 보존되고 원문/번역 소스로 같은 이름을 지정하면 원문 출력을 억제해 덮어쓰기를 막는다.
14. 원문 관측부터 최초 표시까지의 단계별 시각, 갱신·만료·구버전 폐기 수, 큐 깊이를 본문 없는 로그로 확인한다. 기존 `stt_final_ms`는 마지막 interim→final 지표로 유지하고 전체 인식 지연으로 오인하지 않는다.
15. §5의 신규 단위·가짜 전송 통합 테스트, 영향받지 않은 기존 회귀 테스트와 전체 빌드가 exit 0이다. 실제 API·OBS 검증은 별도로 결과와 미검증 범위를 기록한다.

## 4. 기능 범위

### 4.1 공통 식별자와 결과 반영 계약

다음 필드의 의미를 `006`과 공유한다. 이름은 계약 이름이며 클래스 배치는 성공 기준을 만족하는
범위에서 조정할 수 있다. 모델에 ID·구분자·버전 문자열을 출력하도록 요구하지 않는다.

| 필드 | 의미·수명 |
|---|---|
| `generation` | 세션/번역 설정 세대. 정지·재시작·STT 재연결 및 번역 의미에 영향을 주는 설정 변경 시 증가하며 프로세스 내 재사용하지 않는다. |
| `utterance_id` | 첫 non-empty interim 또는 단독 final에서 만든 로컬 발화 ID. final 수신 후 다음 발화는 새 ID다. |
| `segment_id` | 하나의 논리적 구간 ID. 단순 원문 수정 동안 유지하고 병합·재분할 시 새로 발급한다. |
| `order_key` | 발화 순서와 발화 내 위치. 새 ID가 발급되어도 대체된 구간의 표시 위치를 승계한다. ID 숫자로 표시 순서를 추정하지 않는다. |
| `source_revision` | 해당 구간의 번역 대상 원문이 바뀔 때 증가한다. final 여부만 변경되고 원문이 같으면 올리지 않는다. |
| `attempt_id` | 같은 원문 버전의 첫 요청은 1, `006` 교정 요청은 2다. 새 원문 버전에서는 1부터 시작한다. |
| `request_kind` | `initial`, `source_update`, `quality_retry`. SMART 수정은 품질 재시도 예산을 소비하지 않는다. |
| 표시 상태 | `waiting`, `visible`, `retired` 및 페이지 위치·최초 표시·만료 시각. `retired`는 성공 응답으로 되살릴 수 없다. |

작업은 위 식별자, 원문, 이전 문맥, 대상 언어·모델·사전의 불변 스냅샷을 갖는다. 비밀값은
로그나 테스트 fixture에 넣지 않는다. 원문/번역문과 실제 표시 문자열은 별도로 보관한다.

결과 반영 시 하나의 원자적 상태 전이에서 다음을 확인한다.

1. 세대, 활성 구간, 현재 원문 버전과 일치한다.
2. 그 원문 버전에서 현재 유효한 시도 번호와 일치하고 아직 결과를 처리하지 않았다.
3. 표시 대상이 아직 유효하다. 원문 수정으로 구간이 대체되었으면 해당 응답은 폐기한다.
4. 성공은 보관 번역을 교체하며, 실패는 동일 버전/시도에만 적용한다. 이미 보이는 이전 번역을
   교정 실패만으로 지우지 않는다. 아직 아무 번역도 없는 최종 실패는 순서 대기를 해제한다.

`006`이 시도 2를 등록하기 전 시도 1 결과를 임시 표시할 수 있다. 시도 2 등록 이후에는
시도 1의 늦은 이벤트를 무시한다. 새 원문 v3은 v2의 모든 시도보다 우선한다.

### 4.2 final 분할과 interim 선행 번역

기본 튜닝 값은 측정으로 확정된 성능 수치가 아닌 최초 구현의 결정적 테스트 기준이다.

| 항목 | 초기값 / 규칙 |
|---|---|
| 원문 분할 목표 | 80 표시 단위, 최대 120 표시 단위. 자막 박스 크기와 분리한다. |
| 짧은 구간 | 원칙적으로 12 표시 단위 이상. final 잔여 부분과 명확한 문장 끝은 예외다. |
| 안정성 | 내용이 달라진 최근 interim 3개에서 유지되는 접두부이며 해당 접두부가 800ms 이상 변경되지 않아야 한다. 같은 메시지 반복은 관측 수를 올리지 않는다. |
| 선행 방출 조건 | 안정 구간의 문장 끝, 목표 길이 도달, 또는 미번역 내용의 최초 관측 후 2,000ms 경과 중 하나. 마지막 조건도 안정성 검사를 생략하지 않는다. |
| 미완성 꼬리 | 안정 접두부의 마지막 어절은 남긴다. 공백이 없는 구간은 마지막 4개 코드 포인트를 남긴다. 문장 종결 구두점까지 안정된 경우에는 남기지 않아도 된다. |

경계 우선순위는 문장 종결 구두점(`。！？.!?`), 쉼표·세미콜론·명시적 줄바꿈, 공백,
코드 포인트 경계다. `3.14`처럼 숫자 사이의 점은 종결로 보지 않는다. 정규식 어미 추정으로
한국어의 의미 완결을 보장한다고 주장하지 않는다. final은 상한 안의 가장 뒤쪽 경계에서
분할하고, interim은 안정 접두부 안에서만 같은 규칙을 적용한다.

interim은 이어 붙이는 delta가 아니라 현재 미확정 발화의 가설 스냅샷으로 관리한다.
UTF-8 디코딩 후 공백 정리 정도의 정규화만 허용하고 숫자·부정·문장부호를 의미 없이
삭제하지 않는다. 타이머 tick은 관측된 안정성을 평가할 수 있지만 새로운 관측을 만들지 않는다.
한 번 번역한 접두부를 다음 interim에서 다시 방출하지 않는다.

단독 final도 동일 분할기를 거친다. 한 발화의 구간마다 이전 최대 3개 논리적 구간의 최신
원문을 문맥으로 전달하며, 현재 구간·폐기 버전은 제외한다. 길이는 §4.5에서 제한한다.
번역 프롬프트의 박스 크기 기반 압축 힌트는 제거한다. 입력 분할과 출력 페이지 처리로 길이를
관리하고, 모델의 `maxOutputTokens=256` 등 기존 API 설정은 이 스펙에서 변경하지 않는다.

### 4.3 SMART 수정과 final 대조

최종 결과가 오기 전 방출한 구간은 provisional이다. 변경되지 않은 동일 prefix/suffix를
어절·코드 포인트 기준으로 정렬해 수정 구간을 찾되, 같은 단어가 반복되어 대응이 모호하면
정렬 결과를 확정 사실로 취급하지 않는다. 숫자·부정이 바뀌면 공백 변경처럼 무시하지 않는다.

- 경계와 대응이 명확하면 동일 구간의 `source_revision`을 올려 최신 원문 작업으로 교체한다.
  남아 있는 안정 구간은 재번역하지 않는다.
- 경계가 달라지면 영향받는 연속 구간을 새 구간 집합으로 대체하고 `replaces` 관계와 순서
  위치를 기록한다. 번역 중인 옛 구간은 논리적으로 무효화하고 보이는 옛 텍스트는 새 결과가
  준비되거나 표시 시간이 끝날 때까지 임시로 유지한다. final 수신 시의 유지 시간 갱신은 §4.4를 따른다.
- 대응이 모호하고 해당 발화의 어떤 부분도 아직 표시되지 않았다면 전체 가설을 재분할한다.
  표시 중인 구간만 영향받으면 그 표시 슬롯을 대체하되 최소 표시·만료 시각을 승계한다.
- 한 표시 슬롯을 여러 새 구간이 대체하면 첫 새 구간의 결과가 준비된 때 옛 슬롯을 한 번만
  교체하고 나머지는 그 뒤에 둔다. 새 구간 중 뒤쪽 응답이 먼저 와도 먼저 표시하지 않는다.
  여러 슬롯이 하나로 합쳐질 때는 아직 남아 있는 가장 앞 위치를 승계한다. retire 구간까지
  포함되는 모호한 병합은 아래의 보수적 대조 실패 규칙을 따른다.
- 이미 표시가 끝난 구간과 활성/미표시 구간에 걸친 수정의 대응이 모호하면 영향받는 구간을
  무효화하고 그 발화의 추가 선행 번역을 중단한다. final에서도 새 꼬리임을 입증할 수 없는
  내용은 재노출하지 않고 `reconcile_ambiguous`를 기록한다. 정확한 전체 재생을 보장하기 위해
  과거 내용을 다시 띄우는 동작은 하지 않는다. 이 제한은 실사용 검증에서 누락으로 집계한다.
  작업 무효화와 화면 비우기는 분리한다. 이미 표시 중인 창은 유지 시간까지 표시 전용 스냅샷으로
  남기고, 유효한 대체 작업이 없으면 다음 발화의 준비된 자막으로 정상 진행한다.
- final이 현재 원문과 같으면 final 플래그만 확정한다. 다르면 위 규칙으로 대조한다. 처리한
  글자 수로 final을 단순 `substr`하지 않는다. 같은 내용의 연속 발화는 서로 다른 ID로 유지한다.

예상 fixture: 앞부분 삽입, 조사 삭제, `금요일 → 월요일`, `한다 → 하지 않는다`, 반복 단어,
숫자 표기 변경, 한 구간이 두 개로 나뉨, 두 구간이 하나로 합쳐짐, final 전체 재작성.

### 4.4 표시와 페이지 교체

화면은 `002`의 원문과 같은 **최근 줄 창**으로 동작한다. 새 번역을 기존 텍스트에 이어 붙여
폭에 맞게 감고 `caption_max_lines`를 넘은 가장 오래된 줄부터 밀어낸다. 예를 들어 짧은 A·B·C가
한 줄에 들어가면 `A → A B → A B C`가 된다. OBS에는 매번 완성된 전체 창 문자열을 전달한다.

- `wrap_text`의 폭 계산과 구두점 예외를 재사용하고 최대 `caption_max_lines`줄씩 페이지를
  만든다. 확정 여부와 발화 경계에 관계없이 연속 세그먼트는 공백 하나로 이어 붙인 뒤 다시
  감아 남은 줄 폭을 사용한다. 명시적 줄바꿈과 긴 결과의 페이지 경계는 유지한다. 일반적인
  길이 초과는 잘라내지 않는다. 소스 원문 표시는 기존 `wrap_tail`을 유지한다.
- 페이지 최소 표시 시간은 `min(hold_ms, 1,200ms)`다. 다음 페이지/구간이 준비되면 이 시간이
  지난 다음 tick에 창 아래로 붙인다. 준비되지 않았으면 해당 페이지 또는 성공한 교체 결과가
  실제 표시된 시각 + `hold_ms`에 최근 줄 창 전체를 지운다.
- 현재 표시 중인 발화의 최초 final 수신 시에는 원문 대조 전에 `hold_ms`를 다시 계산한다.
  같은 원문 확정뿐 아니라 원문 수정·재분할·모호한 대조 실패에도 기존 화면을 즉시 지우지 않는다.
  수정된 번역이 준비되면 그 결과로 교체하고, 끝내 반영할 결과가 없으면 갱신된 hold에 만료한다.
  이 표시 수명 갱신은 최소 표시 시간·페이지 순서·전체 표시 수명을 변경하지 않는다. 같은 화면의
  반복 확정, 다른 발화의 final, 이미 만료한 화면에는 적용하지 않고 구버전 결과도 계속 거부한다.
- 다음 구간의 응답이 먼저 완료되어도 앞 구간이 성공·실패·만료할 때까지 기다린다. 순서 대기
  제한은 §4.5를 따른다. 한 tick에는 최대 한 번의 페이지 진입만 허용한다.
- 새 버전은 현재 활성 구간의 보이는 페이지와 아직 보이지 않은 잔여 페이지를 원자적으로
  대체한다. 첫 페이지 표시 중이면 전체 새 번역을 재페이지화한다. 여러 페이지 중간에
  수정되면 변경 없는 이미 표시한 prefix를 정렬해 제외한다. 대응이 모호하면 현재 페이지
  교체까지만 허용하고 모호한 나머지는 폐기·계측한다. 이전 페이지로 되돌아가지 않는다.
- 성공한 교체 결과가 실제 표시되면 현재 페이지의 최초 표시·최소 표시·만료 시각을 그 시각에서
  다시 시작한다. 새 구간 집합의 첫 교체 페이지도 같은 규칙을 따른다. 아직 결과가 없거나
  실패·구버전·중복인 콜백은 기존 표시와 시각을 바꾸지 않는다.
- 다음 구간이 진입해 retire된 이전 구간의 최근 줄은 창에서 밀려날 때까지 표시 전용 이력으로
  남지만 늦은 응답으로 수정하지 않는다. 현재 활성 구간의 교체는 동일 창 조각을 바꾸며 중복
  append하지 않는다. 표시 이력은 고정 상한 안에서만 보관한다.
- 만료 시각과 같은 시각에 도착한 교체는 만료가 우선한다. 이후 페이지 전환이나 화면이
  지워진 구간을 늦은 교체로 부활시키지 않는다. 완료된 페이지는 재생하지 않는다.
- 폭·줄 수 변경은 보이는 페이지와 미표시 내용만 다시 감고, 완료한 페이지는 복구하지 않는다.
  hold 변경은 최신 페이지 진입·성공한 표시 교체·현재 발화의 최초 final 수신 중 마지막 시각을
  기준으로 새 만료를 계산한다. 번역
  설정 변경은 §4.6을 따른다.

### 4.5 큐·자원 제한과 스케줄링

| 항목 | 초기 상한·정책 |
|---|---|
| 실제 HTTP 동시 요청 | 기존 3개. 취소 요청을 보냈다는 이유만으로 슬롯을 반환하지 않고 실제 완료/취소 확인 때 반환한다. |
| 시작 전 번역 작업 | 전체 12개. 같은 구간의 구버전 작업을 우선 제거하고 초과 시 가장 오래된 미표시 구간을 retire한다. |
| 미표시 구간 수 | 처리 중·완료 후 표시 대기를 포함해 24개. 초과 시 가장 오래된 미표시 구간부터 retire한다. |
| 최초 표시 대기 | 구간의 최초 작업 등록부터 6,000ms. 수정/재시도는 이 기한을 리셋하지 않는다. tick과 dispatch 전 검사하며 기한이 지나면 `stale_before_display`로 retire한다. |
| 세그먼트 전체 표시 수명 | 현재 번역 버전의 최초 페이지 표시부터 15,000ms. 현재 페이지의 최소 표시 시간은 보장하되 그 이후 미표시 페이지를 만료시킨다. 단일·마지막 페이지의 hold는 이 상한으로 줄이지 않으며, 성공한 표시 교체는 새 버전의 표시 수명을 시작한다. |
| 전체 관리 구간 | 현재 발화의 retire 메타데이터 포함 256개. 상한 도달 시 그 발화의 선행 분할을 중단하고 bounded final 처리로 전환한다. |
| 원문 스냅샷 | 발화당 UTF-8 32KiB, 최대 3개 스냅샷. 초과한 발화는 선행 번역을 중단하고 `source_limit`을 기록한다. final도 초과하면 코드 포인트 경계의 마지막 32KiB만 처리하고 이전 가설과 모호한 겹침은 §4.3처럼 폐기한다. |
| 번역문·문맥 | 구간 번역 최대 UTF-8 16KiB, 문맥은 최대 3개·합계 2KiB. 초과 번역은 오류로 처리하고 문맥은 오래된 구간부터 제외한다. HTTP 응답 본문은 64KiB에서 수신을 중단하거나 클라이언트에서 제한하고 파싱 전에도 검사한다. |

retire한 구간의 번역문은 즉시 해제한다. final 대조에 필요한 현재 발화의 원문·식별 정보만
위 상한 안에서 보관하고, final 대조 완료 뒤에는 활성 표시와 직전 문맥에 필요한 정보만
남긴다. 삭제한 ID는 재사용하지 않으며 저장소에 없는 ID의 응답은 무시한다. 이 상한들은
파싱 후에만 검사하지 않고 입력 수신 경계에서도 적용해 일시적인 무제한 누적을 막는다.

최초 번역과 SMART 원문 수정은 같은 일반 큐다. 구간 순서를 기본으로 하되 표시 중 수정은
다음 dispatch에서 우선하며, 수정 작업을 연속 1개 처리한 뒤 대기 중 최초 번역을 먼저 뽑는다.
같은 구간/버전 중복 요청을 막고, 새 revision이 생기면 아직 시작하지 않은 옛 작업을 교체한다.
실행 중 요청은 가능하면 취소하되 정확성은 취소 성공에 의존하지 않는다.

`006`용 저우선순위 교정 작업 등록 지점을 제공한다. 005 단독 구현에서는 이를 생성하지 않는다.
과부하 폐기, 네트워크 실패, SMART 대조 모호성, 화면 공간 절단을 서로 다른 사유로 계측한다.
상한은 사용자에게 노출할 설정으로 늘리지 않고 초기에는 내부 상수로 둔다.

### 4.6 세션·설정 변경과 락 경계

상태 변경은 하나의 직렬화된 reducer 또는 동등한 락 규칙으로 처리한다. 결과 수락, 화면
스냅샷 생성, 발행 순서가 분리되어 옛 스냅샷이 나중에 써지는 경쟁을 막는다. 네트워크 호출과
OBS sink 호출은 상태 락 밖에서 수행하며 발행 번호를 검증하거나 직렬화해 최신 순서를 보장한다.
오디오 콜백에는 분할·유사도·HTTP 처리를 넣지 않는다.

정지·재시작·키·대상 언어·모델·음성/번역 사전 변경은 세대를 올리고 대기 작업과 표시를
비운다. STT 재연결은 미확정 원문과 작업을 격리하기 위해 세대를 올린다. pause 진입도
연결 종료 시 같은 규칙을 적용하되, 이미 보이는 스냅샷은 기존 만료까지만 유지할 수 있고
옛 응답으로 갱신할 수 없다. `004`의 오디오 pre-roll, 재개와 유휴 판정은 변경하지 않는다.

STT 소켓 재연결 필요 여부는 기존 정책을 따른다. 번역 모델/번역 사전만 바뀌어도 번역 세대는
바뀌지만 STT 소켓을 불필요하게 재연결하지 않는다. 박스·hold 변경은 세대를 바꾸지 않는다.
401/403은 기존처럼 세션을 중단하며, stale 세대의 인증 실패는 현재 세션을 중단하지 않는다.

### 4.7 설정·관측과 기존 스펙 대체 범위

`caption_incremental_translation` bool을 추가한다(기본 `true`). UI에는 “발화 중 미리 번역” /
“Translate while speaking”으로 노출하고 SMART 수정으로 자막이 갱신될 수 있음을 설명한다.
`false`이면 신규 interim 작업만 중단하며 final 분할·결과 버전 관리는 유지한다. 전환 시 현재
미확정 발화의 예약 작업을 무효화하되 이미 표시한 구간을 final에서 중복 생성하지 않는다.

`caption_source_text_source == caption_text_source`인 non-empty 설정은 원문 sink를 비활성화하고
속성창에 서로 다른 소스를 선택하도록 안내한다. 번역 표시를 우선한다.

로그에는 식별자, 요청 종류, 단계별 시간(`segment_wait_ms`, `queue_wait_ms`, `http_ms`,
`display_wait_ms`, `first_seen_to_display_ms`), 큐 깊이, 폐기 사유를 넣는다. 최초 관측은
텍스트 수신 시각이며 실제 발성 시작 시각으로 표현하지 않는다. `hold_ms`와 계측 시계는
단조 시계를 사용한다. 새 기본 로그/성능 fixture에는 원문·번역문·인증 정보를 넣지 않는다.

`001` 기준 3·4의 즉시 누적·hold 의미와 §4.3의 final 전용 작업, §4.5의 선두 대기 정책을
이 문서로 대체한다. `002` 기준 7·8·10·13 중 줄 혼합 창·잘라내기·박스 길이 힌트·옛 표시
회귀 기대를 새 테스트로 대체한다. UTF-8, 폭 계산, 원문 tail, 설정 호환 테스트는 유지한다.

명시적으로 요청한 경우에만 감독자 또는 사용자가 수행한다.

## 5. 검증 방법

아래 명령으로 자동 빌드·회귀 검증을 수행한다. 자동 검증 통과를 실제 OBS/API 성능 검증 완료로
취급하지 않는다. CMake/VS와 의존성이 준비된 저장소 루트에서 실행한다. PowerShell에서도 같은
명령을 사용할 수 있다. VS 2022 환경은 프리셋을 `windows-x64`로 바꾼다.

```bash
# 기준 15: 기존 구성 프리셋으로 설정. API 호출은 없다.
cmake --preset windows-x64-vs2026
# 기준 1–12: S0가 등록할 신규 순수 모듈 + 기존 구성기
cmake --build --preset windows-x64-vs2026 --target caption-segmenter translation-scheduler caption-composer
ctest --test-dir build_x64 -C RelWithDebInfo -R '^(caption-segmenter|translation-scheduler|caption-composer)/' --no-tests=error --output-on-failure
# 기준 5–15: S4가 등록할 가짜 시계·전송 기반 통합 테스트
cmake --build --preset windows-x64-vs2026 --target caption-pipeline
ctest --test-dir build_x64 -C RelWithDebInfo -R '^caption-pipeline/' --no-tests=error --output-on-failure
# 기준 15: 전체 회귀 및 플러그인 빌드
cmake --build --preset windows-x64-vs2026
ctest --test-dir build_x64 -C RelWithDebInfo --no-tests=error --output-on-failure
```

- 기준 2–5: 합성 interim/final fixture와 가짜 단조 시계로 안정성 직전/정확한 경계/직후,
  SMART 정정, 중복, 역순 결과를 재생한다. 실제 시간 sleep이나 외부 API에 의존하지 않는다.
- 기준 10–12: 전송 시작/완료를 barrier로 통제한다. 설정 변경과 응답 수락, stop과 dispatch,
  만료와 sink 발행 순서를 각각 양방향으로 재생한다. 실행 중 요청 수와 활성 메타데이터
  개수의 최대값을 검사한다. 실제 세션 어댑터도 같은 reducer 경로를 사용하는지 검토한다.
- 기준 6–9·13: OBS에서 긴 문장, 연속 문장, 수정 발화를 각각 재생한다. 두 소스 동일 지정,
  박스 변경, final-only 전환, 일시정지·재개도 확인한다. 녹화/화면 관찰로 페이지별 표시와
  수정 위치를 확인하며 final 수신·성공한 표시 교체 시각을 기준으로 설정한 유지 시간이
  지켜지고 실패·구버전·중복 결과로 연장되지 않는지 기록한다.
- 기준 14–15: 동일한 비민감 테스트 음성을 final-only와 incremental로 각각 1회 실행해
  최초 표시 지연 p50/p95, HTTP 요청 수, 누락·정정·모호성 수를 비교한다. 각 실행은 최소
  30개 발화와 60초 연속 발화 구간을 포함한다. 목표는 안정 구간이 있는 연속 발화에서
  final 이전 표시를 관찰하는 것이며 외부 API 지연의 절대 상한을 보장하지 않는다.
  API 사용이 가능한 검증 환경에서만 수행하고 비용 발생·미실행 여부를 결과에 남긴다.
