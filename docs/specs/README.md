# 스펙 인덱스

`docs/specs/`는 obs-live-translate-caption의 기능 스펙을 모은다. 프로젝트 개요(제품 범위, v1
비목표, 아키텍처)는 별도의 `000` 스펙 대신 루트 `README.md`가 담당한다.
새 스펙은 그 둘에서 분리한 기능 슬라이스 하나를 대상으로 작성하고, 아래 표에 한 줄을
추가한다.

| 번호 | 파일 | 대상 | 상태 |
|---|---|---|---|
| 001 | `001-caption-translation-pipeline.md` | STT 전사(`gemini-3.5-transcribe-live`) + LLM 번역(`gemini-3.1-flash-lite`)으로 OBS 텍스트 소스에 번역 자막 출력 | 구현 완료 (2026-09-04 OBS 실사용으로 자막 출력 확인) |
| 002 | `002-caption-text-box-limits.md` | 자막·원문 텍스트를 줄 폭(표시 단위)과 줄 수로 제한해 텍스트 소스 넘침 방지, 잘라내기, 프롬프트 길이 힌트 | 구현 완료 (2026-09-05 OBS 실사용 확인) |
| 003 | `003-remove-speech-mode.md` | speech-to-speech 경로(`TranslationSession`, 오디오 소스, 페이싱)와 `output_mode` 분기를 제거해 자막 전용으로 축소 | 구현 완료 (2026-09-05 OBS 실사용 확인) |
| 004 | `004-idle-pause-and-output-gating.md` | 마이크가 `idle_timeout_seconds`(기본 300) 동안 무음이거나 방송·녹화·가상 카메라가 꺼져 있으면 STT WebSocket을 닫아 API 비용을 멈추고, 링 버퍼는 유지해 재개 시 첫 발화를 보존 | 구현 완료 (2026-09-05 OBS 실사용 확인) |
| 005 | `005-caption-segments-and-versioning.md` | 긴 발화 분할, SMART 수정 대조, 세그먼트·버전 관리, 구간 줄 결합·rolling append·표시 중 교체·hold, 번역 큐·수명 제한 | 구현 완료 / OBS 자막 표시 및 2시간 연속 스모크 확인 (2026-09-12) / 개별·정량 검증 대기 |
| 006 | `006-translation-quality-and-retry.md` | 짧은 공통 프롬프트·자국어 언어명, 로컬 미번역 의심 탐지, 최대 1회 비동기 교정과 우선순위 | 구현 완료 / 전체 빌드·CTest 488/488 통과 및 OBS 2시간 스모크에서 큰 문제 미관찰 (2026-09-12) / 실제 모델·부하 정량 평가 대기 |

005와 006은 2026-09-12 Windows OBS 2시간 연속 스모크 테스트에서 큰 문제가
관찰되지 않았다. 실제 모델 품질과 OBS 부하, API 지연·요청 수·누락률의 개별·정량
비교는 아직 수행하지 않았다. 공통 식별자와 결과 반영
계약은 005 §4.1을 따른다. 005는 001의 final 전용 처리와 002의 줄 혼합·절단 표시를,
006은 001의 프롬프트·품질 처리 일부를 대체한다. 기존 문서의 구현 완료 표시는
기존 범위에 한정하며 신규 스펙의 실사용 검증 완료를 뜻하지 않는다.

## 규칙 요약

- 파일명은 `NNN-kebab-case-name.md`, 번호는 3자리, 인덱스의 다음 번호를 쓴다.
- 범위 표기는 물결표(`~`)가 아니라 en dash(`–`)를 쓴다.
- 스펙은 결정의 기록이다. 대안 나열로 끝내지 않고 결정과 근거를 적는다.
- 구현 슬라이스의 소유 경로는 슬라이스 간 겹치지 않게 나눈다. 공유 파일(`CMakeLists.txt`,
  `tests/CMakeLists.txt`, `README.md`)은 소유 슬라이스를 하나만 둔다.
- 에이전트는 종료 전 §5 검증 명령을 실행하고 exit code를 보고한다. 훅 우회
  (`--no-verify`)와 git 상태 변경(commit/stage)은 감독자 또는 사용자만 수행한다.
