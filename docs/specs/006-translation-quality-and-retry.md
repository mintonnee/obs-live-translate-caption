공통 프롬프트를 줄인다. 로컬 검사와 기존 1회 교정 계약은 유지하며, 자동 빌드·회귀 검증과
실제 모델/OBS 검증 결과를 구분해 기록한다.

## 1. 목표와 비목표

검증 문장:

```text
일본어 자막에 한국어 원문이 그대로 남는 의심 결과는 첫 표시를 재번역 완료까지 막지 않고 최대 한 번 교정하며, 정상 고유명사는 불필요하게 재요청하지 않고 만료·구버전 응답은 표시를 덮어쓰지 않는다.
```

## 2. 성공 기준

1. 모든 요청에 대상 언어의 자국어 이름·BCP-47 코드와 짧은 공통 지시를 포함한다. 등록된 `ja`, `ko`, `fr`는 각각 `日本語 (ja)`, `한국어 (ko)`, `Français (fr)`로 전달하며 지역 코드와 미등록 코드의 fallback은 §4.1을 따른다. `ja`, `ja-JP`, `ko`, `fr`, `en`, `pt-BR`, `pt-PT`의 사전 없는 첫 요청은 system instruction이 UTF-8 400바이트 이하이고 일본어 전용 규칙·기본 예시가 없다. 문맥은 참고만 하며 현재 원문만 번역하도록 지시한다. 교정 시에도 언어별 규칙을 추가하지 않고 §4.4의 짧은 공통 재번역 지시만 붙인다.
2. STT 사용자 사전 `로블록스`는 기존 인식 힌트와 번역 요청의 고유명사 보조 목록으로 전달한다. 이름 목록은 지정 출력 표기나 로컬 검사 예외를 만들지 않는다. 이름이 없으면 보조 목록도 보내지 않는다.
3. 기본 fixture에서 일본어 대상의 `오늘 로블록스 할까요? → 오늘 로블록스 할까요?`와 `로블록스 → 로블록스`는 `suspected`다. `Roblox → Roblox`와 숫자만 있는 입력은 자동 재번역하지 않는다.
4. 전체 유사도가 낮아도 `今日は로블록스で遊びます。`처럼 원문에서 온 한글이 남은 결과는 §4.3의 잔존 규칙으로 탐지한다. 단, fixture의 한글 연속 구간은 실제 원문과 정확히 대응하는 것으로 구성한다.
5. 짧은 라틴 문자 입력, 영어→프랑스어의 동일 문자열, 가나가 없는 한자·브랜드 출력은 문자 종류나 유사도만으로 실패 처리하지 않는다. 근거가 부족하면 `indeterminate`로 표시를 허용하고 자동 재번역하지 않는다.
6. 검사기는 UTF-8 입력과 빈 문자열·혼합 문자·긴 문자열을 처리하며 §4.3의 길이 상한을 지킨다. 외부 서비스·오디오 콜백을 호출하지 않는다. 의미 유사도 API는 없다.
7. `suspected` 첫 결과는 가벼운 검사 후 바로 최초 표시 후보가 된다. 교정은 실제 visible이 된 구간에 한해 예약하며, 같은 `(generation, segment_id, source_revision)`에서 최대 한 번만 실행한다.
8. 교정 성공은 `005` 계약으로 현재 visible 구간만 교체한다. 교정 중 원문 변경·설정 변경·만료·stop이 발생하면 옛 결과를 무시한다. 새 revision은 첫 시도 1로 시작한다.
9. 교정 결과가 다시 `suspected`이거나 HTTP/파싱 실패면 세 번째 요청을 만들지 않고 현재 표시를 유지하며 다음 자막 처리를 계속한다. `indeterminate`도 자동 교체하지 않는다. 현재 세대의 401/403은 기존 `AuthError` 정지 규칙을 따른다.
10. 가짜 전송기로 전체 실행 수가 3 이하, `quality_retry` 실행 수가 1 이하임을 확인한다. 일반 큐에 작업이 있으면 새 교정은 시작하지 않는다. 활성 교정 1개 때문에 나머지 2개 슬롯까지 교정이 점유하지 않는다.
11. 교정 예약 후 만료까지 1,000ms 미만이면 dispatch하지 않는다. 교정 큐는 4개 이하이며 일반 큐가 계속 바쁘면 교정이 실행되지 않은 채 만료되는 것을 허용한다.
12. 설정 키 누락은 §4.6 기본값으로 동작한다. 폐기한 설정 키는 읽거나 기본값·UI를 등록하지 않으며 설정 오류나 세대 변경을 일으키지 않는다. 교정 기능을 끄면 신규 교정을 중단하고 이미 실행 중인 교정의 표시 반영도 차단한다.
13. 로그로 검사·HTTP·큐 대기를 분리하고 의심률, 재시도율, 교정 채택률, 만료 폐기 수를 산출할 수 있다. 일반 로그와 성능 결과에는 원문·번역 본문·사전 내용·인증 정보가 없다.
14. §5의 판정 fixture·스케줄러·파이프라인 통합 회귀와 전체 빌드가 exit 0이다. 로컬 검사 성능 및 실제 모델 품질은 별도로 측정하고 미측정 상태를 통과로 표기하지 않는다.

## 4. 기능 범위

### 4.1 짧은 공통 프롬프트

프롬프트는 `짧은 공통 지시 + 설정된 이름 목록 + 교정 시 짧은 추가 지시`로
조립한다. 일본어를 포함해 모든 언어가 같은 경로를 사용하며 언어별 규칙·고정 번역 예시를
넣지 않는다. 이전 문맥과 번역할 원문은 기존 user 입력의
`Context:`와 `Translate:` 블록으로 구분한다.

공통 지시는 대상 언어 이름·코드, 번역문만 출력, 문맥은 참고만 사용, 자막체와 의미 보존,
미완성 발화를 임의로 완성하지 않음으로 줄인다. 현재 공통 지시의 대상 언어 출력 강조도
유지한다. 원문 언어를 한국어로 고정하지 않는다. 사전 없는 첫 요청의 길이는 성공 기준 1로 회귀 검사하며,
설정한 이름 목록까지 자르거나 새 출력 길이 제한을 만들지는 않는다.

2026-09-12 대상 언어명만 영어에서 자국어 표기로 변경한다. `languages.hpp`의 표시 이름에서
괄호 앞 자국어 부분을 사용하며, 괄호가 없는 `English` 등의 이름은 그대로 사용한다.
`pt-BR`와 `pt-PT`는 이름이 모두 `Português`여도 BCP-47 코드로 구별한다. 목록에 없는 코드는
기존처럼 코드 자체를 이름으로 사용한다. UI 표시 이름·선택 값과 프롬프트의 나머지 문구는
바꾸지 않는다. 자국어 이름이 출력 품질을 개선하는지는 실제 모델 비교 전까지 미검증이다.

일본어 원문 복사·한글 잔존 검사는 프롬프트와 별개인 §4.3의 로컬 로직으로
유지한다. 첫 요청과 후속 요청은 독립적으로 같은 공통 지시를 받는다. `005`에서 제거한
박스 길이 압축 힌트를 복구하지 않는다. 기존 모델 선택, `maxOutputTokens=256`,
샘플링/thinking 파라미터 생략은 유지한다.

### 4.2 음성 인식 사용자 사전

기존 `caption_custom_vocabulary`는 STT 인식 힌트로 유지한다. 번역에는 이름임을 알려주는
보조 목록으로 전달하지만 원문 철자를 강제하지 않으며 로컬 품질 검사의 예외로 사용하지 않는다.
이름의 번역 표기는 모델이 결정한다. 이 목록은 단어별 출력 표기 매핑이 아니다.

2026-09-12 번역 표기 사전의 설계와 구현을 제거한다. 이전 설정에 남은
`caption_translation_glossary`는 읽거나 검증하지 않는다. 저장된 OBS 설정 파일을 변경하는
마이그레이션은 수행하지 않으며, 이 키만 달라져도 STT 재연결이나 번역 세대 변경은 없다.

### 4.3 로컬 판정

결과는 번역의 의미적 정답 판정이 아닌 아래의 운영 분류다.

| 결과 | 의미 | 자동 동작 |
|---|---|---|
| `normal` | 검사 범위에서 강한 미번역 신호가 없다. 정확한 번역임을 보장하지 않는다. | 표시 허용 |
| `suspected` | 원문 복사나 한글 잔존의 강한 신호가 있다. | 첫 결과 표시 허용, 조건 충족 시 교정 후보 |
| `indeterminate` | 짧거나 모호하거나 지원하지 않는 언어쌍이라 판정 근거가 부족하다. | 표시 허용, 자동 교정 없음 |

검사는 작업 스냅샷의 대상 언어·원문과 번역 결과로 수행한다. 최신 설정을 중간에 섞지 않는다.
UTF-8을 코드 포인트로 읽고 공백 정리, 비교용 문장부호 제거, ASCII 대소문자 접기만 수행한다.
숫자·문자·한글 자모는 보존하며 가독성 있는 원문 자체는 수정하지 않는다. 유니코드 전 범위의
정규화나 완전한 언어 판별을 구현했다고 표현하지 않는다.

1. API/파싱 오류나 빈 결과는 기존 번역 실패 경로다. 품질 교정을 생성하지 않는다.
2. 전체 입력과 출력이 숫자·기호·URL만으로 구성되면 `normal`이다.
3. 일본어 대상에서는 다음을 검사한다.
   원문 한글이 2개 이상이고 비교용 원문/출력이 같으면 `suspected: source_copy`다.
   출력에 원문에서 그대로 가져온 한글 연속 구간이 4개 이상이면
   `suspected: hangul_residue`다. 완성형 한글과 자모 블록을 포함한다.
4. 위 조건으로 판정하지 못한 후보에 한해 문자열 유사도를 보조 계산한다.
   `similarity = 1 - edit_distance / max(source_length, output_length)`를 사용한다.
   두 길이가 모두 0이면 예외로 처리하며, 각 문자열이 256 코드 포인트 이하일 때만
   두 행 DP로 계산한다. 일반 문자가 8개 이상이고 유사도 0.90 이상이며 일본어 출력에
   원문에서 온 한글이 2개 이상 남으면 `suspected: near_copy`다.
5. 일본어의 가나가 없다는 사실, 원문/출력이 라틴 문자라는 사실, 유사도 단독으로는
   `suspected`가 되지 않는다. 한글 없는 짧은 동일 이름(`Roblox`, `OK`)은
   `indeterminate`이고 자동 교정하지 않는다. 나머지 지원 범위의 일본어 출력은
   `normal`, 일반 fallback 언어는 숫자·기호·URL 예외 외에는 `indeterminate`다.

유사도 0.90 등의 수치는 초기 정책이며 §5의 라벨 fixture로 조정한다. 의미 임베딩 유사도는
정상 번역도 높게 나와 미번역 판단 근거가 아니므로 사용하지 않는다. 256 코드 포인트 초과는
유사도만 생략하고 문자 검사는 `005`의 입력 상한 안에서 계속 수행한다.
정규식 catastrophic backtracking이 가능한 패턴이나 무제한 부분 문자열 DP는 사용하지 않는다.

한글 1–3자의 부분 잔존, 동의어 오역, 문장 일부의 누락은 탐지하지 못할 수 있다. 인용문에서
한글을 보존해야 하는 경우도 오탐이 가능하며 자동 교정이 불필요하면 교정 기능을 끌 수 있다.
이 한계를 정확도 지표에서 숨기지 않는다.

### 4.4 교정 요청과 버전

동기 로컬 검사 후 첫 응답은 정상 표시 흐름에 넣는다. `suspected`이면 사유만 붙여 두고,
실제로 그 구간이 화면에 들어온 때 교정 예약 조건을 평가한다. 기다리는 구간을 교정하느라
최초 표시를 늦추지 않는다. 짧은 페이지는 교정이 끝나기 전에 지나갈 수 있다.

교정은 `005`의 동일 `generation`, `utterance_id`, `segment_id`, `source_revision`으로
`attempt_id=2`, `request_kind=quality_retry`를 사용한다. 첫 요청과 동일 원문·문맥·모델·언어·
이름 목록 스냅샷에 모든 의심 사유 공통으로 “원문을 대상 언어로 다시 번역하고 교정된 번역문만
출력”하는 한 문장만 붙인다. 성공 기준 1의 언어들에서 추가 지시는 UTF-8 128바이트 이하다.
판정 사유는 로컬 판정·로그에 유지하지만 긴 사유별 지시나 일본어 규칙을 추가하지 않는다.
이전 오답 번역을 원문 대신 번역하지 않는다.

한 원문 버전에서 교정 시작은 최대 1회다. 예약 중복은 하나로 합치며 queue 퇴출·기능 해제·
만료 뒤 동일 버전으로 반복 예약하지 않는다. 교정 결과를 같은 로컬 검사로 확인하고
`normal`인 경우에만 표시 중 구간에 반영한다. `suspected`/`indeterminate`/오류면 현재 번역을
유지하고 교정을 종료하며 다음 자막 처리를 계속한다. 품질 실패를 원래 구간의 `on_failed`처럼
처리해 자막을 지우지 않는다. 여기서 실패 후 넘김은 해당 교정을 포기한다는 뜻이다.

교정 예약에는 당시 표시 페이지의 토큰과 만료 시각도 저장한다. 같은 세그먼트라도 다음
페이지로 넘어갔으면 이 교정 결과를 폐기한다. 별도 요청 버전 체계가 아니라 표시 수명
검사에 필요한 스냅샷이며, 결과 수락 시 페이지 토큰까지 원자적으로 확인한다.

SMART 원문 v3이 생기면 v2 교정은 무효다. v3은 원문이 다른 새 일반 번역이며 시도 1과
독립적인 1회 교정 예산을 갖는다. 원문 수정이 반복되어도 `005`의 작업 합치기·전체 수명·
큐 상한으로 제한한다. 결과 수락과 visible 확인은 동일 상태 전이에서 처리한다.

### 4.5 3개 슬롯 안의 우선순위와 만료

| 항목 | 결정 |
|---|---|
| 전체 실행 HTTP | 최대 3개, `005`와 동일 풀 |
| 품질 교정 실행 | 최대 1개. 별도 워커를 늘리지 않는다. |
| dispatch 우선순위 | `005`의 최초/원문 수정 작업을 먼저 선택한다. 일반 큐가 비고 슬롯이 남을 때만 교정 1개를 시작한다. |
| 교정 예약 큐 | 최대 4개이며 `005`의 전체 시작 전 작업 12개 상한에도 포함된다. 동일 버전 중복은 합친다. |
| 예약·시작 조건 | 현재 visible이며 최신 원문 버전이고 기능이 켜져 있으며 현재 페이지 만료까지 1,000ms 이상 남아 있어야 한다. |
| 만료 기한 | 예약 당시 페이지 만료 시각과 현재 페이지 만료 시각 중 이른 시각. 페이지 전환으로 기한을 연장하지 않는다. |
| 교정 타임아웃 | 남은 유효 시간 이내의 전체 요청 deadline을 적용하고 기존 연결·전송 제한보다 길게 잡지 않는다. |
| 과부하 | 일반 작업 때문에 전체 큐 한도에 도달하면 교정 예약부터 제거한다. 교정 큐가 가득 차면 새 후보를 생략한다. |

교정이 이미 실행 중일 때 새 일반 작업이 오면 나머지 슬롯으로 시작한다. 실행 중 교정을
논리적으로 취소해도 실제 HTTP 완료 전에는 슬롯이 빈 것으로 계산하지 않는다. 클라이언트가
정밀 deadline 취소를 지원하지 않으면 스케줄러에서 기한 경과 결과를 버리고 실제 요청은
기존 타임아웃 안에서 끝나도록 한다. 이 경우 네트워크 점유 지연을 따로 기록한다.

따라서 교정이 일반 번역에 전혀 영향을 주지 않는다고 보장하지 않는다. 일반 부하가 크면
교정이 한 번도 시작하지 않아도 정상 정책이다. HTTP 429·5xx·타임아웃은 품질 재시도 연쇄를
만들지 않으며 HTTP 401/403은 현재 세대인 경우에만 세션을 멈춘다.

### 4.6 설정·로그

| 키 | 타입·기본값 | 의미 |
|---|---|---|
| `caption_quality_retry` | bool, `true` | 로컬 의심 탐지에 따른 자동 교정을 허용한다. 꺼도 검사·계측과 공통 프롬프트는 유지한다. |

UI는 “미번역 의심 시 한 번 재번역” / “Retry suspected untranslated captions once” 체크박스를 제공한다.
검사 임계값·워커 수를 일반 UI에 노출하지 않는다. 한국어·영어 locale과 두 README를 갱신한다.

대상 언어/모델 변경은 `005`의 세대 변경으로 기존 작업을 무효화한다.
`caption_quality_retry=false`는 일반 번역 세대를 바꾸거나 자막을 지우지 않고 교정 작업만
예약 취소·논리 무효화한다. 다시 켜도 같은 버전에서 이미 소모/종료한 교정을 되살리지 않는다.

로그는 식별자, 원문/출력 코드 포인트 수, 적용 규칙, 판정, `detect_us`, 유사도 또는 생략 사유,
`retry_queue_ms`, `retry_http_ms`, `retry_outcome`만 기록한다. 결과 사유는 최소
`accepted`, `still_suspected`, `indeterminate`, `expired`, `superseded`, `disabled`,
`queue_full`, `http_failure`를 구분한다. 지표 분모는 검사한 첫 번역 수·예약한 교정 수·실행한
교정 수를 각각 보관해 혼동하지 않는다. 품질 판정의 오탐률은 사람이 라벨한 평가 데이터로만
계산하며 런타임 `normal` 수를 정답률로 표현하지 않는다.

`finishReason=MAX_TOKENS` 등의 생성 중단은 미번역과 다른 원인이다. 구현 시 응답에 존재하면
진단 사유로 보존하고 해당 결과를 품질 교정 대상으로 삼지 않는다. 출력 토큰 상한 조정·
이어쓰기 복구는 이 스펙의 범위에 포함하지 않는다. 본문이 있는 부분 응답의 기존 표시 여부는
유지하되 로그에서 정상 종료와 구분한다.

## 5. 검증 방법

아래는 구현 검증이다. 2026-09-11 프롬프트 간소화 후 관련 모듈 120/120, 전체 CTest
514/514와 전체 플러그인 빌드가 exit 0이다. 일본어 전용 규칙·예시 제거, 공통 프롬프트 길이,
모든 교정 사유의 짧은 추가 지시와 원문·문맥·생성 설정 보존을 요청 빌더 테스트로 확인했다.
기존 회귀로 첫 표시 비차단·1회 교정 후 종료·만료/구버전 폐기도 확인했다. 실제 모델 품질·
지연 및 OBS 부하는 아직 측정하지 않았으며 미측정 상태를 통과로 표기하지 않는다.
005와 같은 CMake/VS 준비 조건을 적용한다. 이 환경에서는 샌드박스의 MSBuild FileTracker
접근 거부 후 승인된 권한으로 빌드를 수행했다.

2026-09-12 자국어 언어명 적용 후 전체 플러그인 빌드와 CTest 516/516이 exit 0이다.
자국어 이름 조회, 괄호가 없는 이름, 지역 코드 구분, 미등록 코드 fallback과 첫 요청·교정 요청의
언어명 전달을 검증했다. 작업 시작 시점의 프롬프트 본문은 그대로 보존했으며,
기존 테스트와 문서는 현재 본문의 대상 언어 출력 강조에 맞췄다. 실제 모델의 품질 개선 여부는 미측정이다.

2026-09-12 번역 표기 사전 제거 후 전체 플러그인 빌드와 CTest 488/488이 exit 0이다.
사용자의 Windows OBS 2시간 연속 스모크 테스트에서 큰 문제는 관찰되지 않았다.
이 결과는 아래의 조건별 모델 품질·재시도율·OBS 부하 정량 비교를 대체하지 않는다.
매핑 전용 모듈·테스트와 fixture를 제거했고, 남은 42개 fixture에서 원문 복사·한글 잔존·근접
복사 및 비재시도 대상을 검증했다. STT 사용자 사전·자국어 언어명·1회 교정·만료/구버전
폐기 회귀도 통과했다. 폐기한 설정 키와 매핑 타입·판정이 소스·UI·빌드 등록에서 제거되었음을
검색으로 확인했다. 기존 OBS 설정 파일은 수정하지 않았으며 실제 OBS/API 검증은 미실행이다.

- 기준 7–11: 첫 응답 표시 전에 두 번째 HTTP를 기다리지 않는지, 일반 3개 실행 중 교정이
  시작하지 않는지, 일반 2개+교정 1개에서 추가 교정이 시작하지 않는지 barrier로 검사한다.
  visible 진입·만료 직전/정확한 경계, 교정 실패, 결과 역전, SMART revision 변경,
  기능 OFF→ON, 설정 변경과 stop을 가짜 시계·전송기로 재생한다.

  p95 1,000µs 이하를 초기 목표로 둔다. 이는 아직 측정하지 않은 목표이며 환경에 민감한

  분석하고 결과를 문서에 남긴다.
- 기준 1–2: `ja`, `ja-JP`, `ko`, `fr`, `en`, `pt-BR`, `pt-PT`의 짧은 공통 지시·언어별 예시
  없음·길이 상한, 자국어 이름 조회·지역 코드 보존·미등록 코드 fallback, 선택적 이름 목록과
  모든 의심 사유의 짧은 재번역 지시를 요청 빌더 테스트로 확인한다.

  ② 짧은 공통 프롬프트만 ③ 짧은 공통 프롬프트+교정을 비교한다. 각 조건에서 같은 문장당 3회 요청하고 시작 직후
  문맥 없음과 이전 3개 구간 문맥을 구분한다. 1차 비교와 이후 튜닝 평가 표본을 분리한다.

  오탐/미탐·교정 채택/실제 개선률을 기록한다. 문자열 길이 감소를 실제 지연 개선율로 해석하지 않는다.
